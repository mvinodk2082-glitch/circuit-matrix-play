Model notes · what this does and does not promise

Nodal analysis and trapezoidal history

Every branch uses i = g·v + j. For a capacitor: g = 2C/h, j = −g·v_prev − i_prev. For an inductor: g = h/(2L), j = i_prev + g·v_prev. After a successful solve, actual branch voltage and current become the next step's histories. Failed solves never advance state.

Initial v₀ and i₀ are physical branch histories, not a DC operating-point solution. RC and RL presets supply consistent histories explicitly. Arbitrary edits can violate KCL at t=0; this is disclosed, not automatically repaired.

Voltage sources are finite Norton equivalents

A voltage source E with positive finite resistance Rs stamps g = 1/Rs and j = −E/Rs. It is exactly the Norton equivalent of a voltage source in series with Rs, not an ideal zero-impedance voltage source. Source loading error is physical to this chosen model; tiny Rs can amplify conditioning problems. No ideal-source MNA constraint is implemented.

Numerical diagnostics are not hidden

The engine uses scaled partial-pivot Gaussian elimination. κ∞ is computed from the assembled matrix and inverse-column solves, not from the pivot ratio. Both diagnostics warn above 10⁸. Singular or numerically unresolved systems stop with their matrix still visible. No implicit grounding resistor, damping, timestep cap or state clamp is added. Trapezoidal integration can ring for large steps; stable does not mean accurate. The trace keeps the latest 600 samples.

Deferred, unverified specifications — not implemented

The shared engine, passives page and graphical R/C/L/V/I construction workspace are built. No sensors, switch models, PMSM or inverter are included. Confirmed for later stages: trapezoidal Pejovic matching C = h²/(4L); sensor forward gain 0.01, inverse calibration ratio 100. The Quasi-Supra closed-state identity remains insufficient as an algorithm.

The caller confirmed these mathematical corrections after v0.1.0. They are documented here only; none of those later models is implemented or claimed validated. An identity alone does not define the Quasi-Supra update algorithm; authoritative open-state and relaxation equations are still needed.

Scope and validation boundary

This is an educational, linear lumped-circuit model using JavaScript double precision. It is not hardware-in-the-loop, not a protection model and not a validated OPAL-RT / FPGA equivalent. Analytic checks cover selected cases only. No agreement with OPAL-RT results is claimed. All code is inline; no framework, library, build step, telemetry or network call is used.
